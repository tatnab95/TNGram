# Тнграм — приложение

Приложение мессенджера «Тнграм» на движке **Godot 4.7** (GDScript, без сторонних библиотек).
Есть интерфейс, хранение переписки **на устройстве** и связь двумя способами: через **свой
сервер-передаточник** (внутри одной сети) и через **облако Supabase** (из любой точки интернета).
В обоих случаях сервер держит сообщение ровно до момента, пока его не заберёт получатель.

## Как запустить

**Чтобы общаться с другим компьютером — просто запусти `run.bat` на обоих.** Всё, ничего больше
не нужно: приложение само подключается к облаку. (Так же и на любом новом компьютере.)

Если Godot установлен в другом месте, открой файл `.bat` и поправь путь `GODOT_EXE` в первой строке.

Другие способы:

- **`start.bat`** — приложение **и** свой сервер-передаточник в отдельном окне. Нужен только для связи
  **без интернета, в домашней сети**: запускай его **на одном компьютере**, а на остальных впиши
  напечатанный адрес (`ws://192.168.x.x:7777`) в `Настройки → Связь`. Посмотреть адрес, ничего не
  запуская: **`start.bat info`**.
- двойной клик по **`run.bat`** — только приложение (обычный способ, через облако);
- из редактора Godot: `Project → Open` → выбрать папку `tn-gram_godot` → `F5`;
- **`test.bat`** — автопроверки без окна: сначала интерфейс и данные, потом своя сеть;
- **`cloud_test.bat`** — проверка облачной связи по-настоящему, через интернет;
- **`relay.bat`** — только сервер-передаточник (держи открытым, пока общаешься);
- **`run_second.bat`** — второе окно приложения со своим профилем (для проверки связи на одном ПК);
- **`firewall.bat`** — открыть входящий порт `7777` в файрволе Windows (спросит права администратора).
  Нужен только для `start.bat`, то есть для домашней сети.

## Облако: связь из любой точки (и это способ по умолчанию)

Свой сервер виден только внутри одной сети. Чтобы писать человеку из другого города, есть облако —
бесплатный проект **Supabase**. Платить не надо, свой сервер держать не надо, твой компьютер может быть
выключен (сообщение подождёт в облаке).

**Ничего вписывать не нужно:** адрес и ключ облака уже встроены в приложение, и на любом компьютере
оно подключается само при входе. Просто запусти `run.bat` и войди.

Если понадобится вписать руками (или вернуться к своему серверу) — это в `Настройки → Связь`:

- адрес: `https://hqmgjnloilemdwejzoyy.supabase.co`
- ключ: `sb_publishable_eyJSH1Zs1IDEeE61009XDw_cQt5ujXj`

Ключ не секретный, его можно передавать. А вот **секретный** ключ (`service_role`) никому не показывай.

Как это работает: сообщение ложится строкой в таблицу облака. Если получатель на связи, он узнаёт о нём
мгновенно и **сразу удаляет** у себя; если офлайн — сообщение ждёт в облаке и придёт, как только он
подключится. Обещание то же, что и у своего сервера.

Проверить, что облако живо: **`cloud_test.bat`** — 22 проверки по-настоящему через интернет
(а если в облаке уже есть таблицы из `Обновление-1.6.sql` — ещё 4: кто в сети и новости).

**Чтобы бесплатный проект не «засыпал»** после 7 дней без запросов, нужно, чтобы кто-то раз в сутки
дёргал облако. Два способа — хватит любого одного:

1. **Через GitHub** (если проект залит на GitHub): в репозитории лежит
   `.github/workflows/keepalive.yml` — он каждый день в 04:23 UTC делает один безобидный
   запрос. Нужно, чтобы репозиторий был залит и в разделе **Actions** задача была включена
   (Settings → Actions → General → Allow all actions). Если репозиторий «молчит» 60 дней,
   GitHub сам выключает задачи — тогда включи их заново.
2. **Без GitHub:** заведи бесплатную задачу на https://cron-job.org — адрес для запроса:
   `https://hqmgjnloilemdwejzoyy.supabase.co/rest/v1/messages?select=id&limit=1`,
   метод GET, и два заголовка (Headers):
   `apikey: sb_publishable_eyJSH1Zs1IDEeE61009XDw_cQt5ujXj`
   `Authorization: Bearer sb_publishable_eyJSH1Zs1IDEeE61009XDw_cQt5ujXj`
   Расписание — раз в сутки. Ожидаемый ответ: 200.

Если облако всё-таки заснуло — оно не потеряется: зайди на supabase.com в свой проект и нажми
«Restore»/«Resume»; данные останутся на месте.

> **Важно про безопасность.** Сейчас облако пускает любого, у кого есть публичный ключ: серверной
> аутентификации ещё нет. Для проверки с друзьями это нормально, но **перед реальными 50 пользователями
> нужно добавить вход** (логин и пароль на сервере). Пока ключ есть у постороннего — он может прочитать
> таблицу сообщений.

## Настройка облака: один шаг в Supabase (нужно сделать один раз)

В облаке нужно две таблицы: **занятые ники** и **номер последней версии**. Обе создаются одним
запуском:

1. Открой https://supabase.com/dashboard/project/hqmgjnloilemdwejzoyy/sql/new
2. Скопируй туда **всё** содержимое файла `supabase/Облако.sql`.
3. Нажми **Run**. Должно появиться `Success. No rows returned`.

Этот шаг безопасно повторить: код ничего не ломает, если уже сделано.

Что это даёт:

- **Ники бронируются** — один ник не могут занять двое (`Админ` и `админ` — один ник, изменять и
  удалять ники через публичный ключ нельзя). Пока таблицы нет, приложение всё равно работает:
  ник бронируется только на твоём устройстве, а «Новый чат» открывается без проверки.
- **Приложение узнаёт про новые версии** — читает номер версии прямо из облака, поэтому сайт на
  GitHub для этого больше не нужен.

**Как выпустить новую версию** (когда что-то поправишь):

1. Подними номер в `scripts/net/Protocol.gd` (`APP_VERSION`), допиши изменения в `CHANGELOG`
   там же — они появятся на экране «Что нового».
2. В Supabase → SQL Editor выполни:
   ```sql
   update public.version set version = '1.3', notes = 'Что нового…', updated_at = now() where id = 1;
   ```
3. Собери новый `.exe` и разошли его. Приложения у людей сами скажут: «Вышла новая версия».

Проверка обновления идёт сначала в облако, а если облако недоступно — смотрит на сайт
(`сайт/version.json`, если он когда-нибудь появится). Ничего не найдено — просто молчит, это не
ошибка и работе не мешает.

## Сайт приложения (по желанию)

Экран «Что нового» работает всегда — список изменений лежит в самом приложении. Сайт для проверки
обновлений **больше не обязателен** (номер версии читается из облака), но если захочешь его
опубликовать — в репозитории уже настроен `.github/workflows/pages.yml`:

1. Загрузи репозиторий на GitHub. **Важно:** на приватном репозитории бесплатный GitHub Pages
   не работает — либо репозиторий должен быть публичным, либо сайт не нужен (см. выше).
2. В репозитории: **Settings → Pages → Source: GitHub Actions**.
3. Открой **Actions → Deploy site → Run workflow** (или просто сделай следующий коммит) и дождись
   зелёной галочки. Сайт появится по адресу `https://tatnab95.github.io/TNGram/`.

Проверить: открой в браузере `https://tatnab95.github.io/TNGram/version.json` — должен показаться
короткий JSON с номером версии. Адрес сайта по умолчанию — `Protocol.SITE_URL`; поменять его можно
там же, в `Protocol.gd` (поля для адреса сайта в интерфейсе нет).

## Связь: как проверить прямо сегодня

Ни аккаунтов, ни интернета, ни чужих сервисов не нужно — всё работает на твоём компьютере.

1. Запусти **`relay.bat`** — консоль напишет, что сервер слушает порт `7777`. Оставь её открытой.
2. Запусти **`run.bat`**, войди как `админ`.
3. Запусти **`run_second.bat`** — откроется второе окно со своим профилем, войди как `админ2`.
4. В каждом окне: `Настройки → Связь → адрес 127.0.0.1:7777 → Подключиться`.
   Если включишь галочку «Подключаться при входе», вставать на связь будет само.
5. Напиши что-нибудь из одного окна — сообщение появится в другом.

Что происходит в это время: сообщение сохраняется у тебя, уходит на сервер, сервер держит его и
отдаёт получателю, получатель подтверждает — и сервер **сразу удаляет** у себя. Если получатель
оффлайн, сообщение подождёт на сервере и пришлётся, как только он выйдет на связь.

Для людей в той же домашней сети подключайся не к `127.0.0.1`, а к адресу этого компьютера —
`start.bat` печатает его готовым. Windows при первом запуске может спросить «разрешить доступ» —
согласись, иначе порт будет закрыт (то же самое делает `firewall.bat`).

## Как проверить с другом из другого города

**Ничего настраивать не надо.** Облако уже встроено: запусти приложение и войди — и пусть друг сделает
то же самое. Вы оба окажетесь в одном общем месте и увидите друг друга.

Другу нужно **переслать один файл** `build\TNGram.exe` (и, по желанию, `build\ПРОЧТИ-МЕНЯ.txt`
и `build\TNGram-качество.bat`).
Скачивать и ставить ничего не нужно: запустил и всё. Обычное синее окно Windows «Подробнее» →
«Выполнить в любом случае» — это ожидаемо для новой программы без платной подписи.

Если хочется обойтись без облака, есть ещё два пути:

1. **Tailscale** — поставь Tailscale себе и другу, войдите под одним аккаунтом. `start.bat` сам
   напечатает адрес вида `ws://100.x.y.z:7777`; продиктуй его другу, он впишет его в
   `Настройки → Связь`. Канал Tailscale сам прокладывается через интернет, роутер настраивать не надо.
   Оговорка: на бесплатном тарифе только **3 пользователя**, для большой компании не подойдёт.
2. **Проброс порта** — если провайдер даёт «белый» IP: в роутере пробрось TCP `7777` на этот
   компьютер, открой порт в файрволе (`firewall.bat`) и продиктуй другу внешний адрес. При «сером»
   IP (за NAT провайдера) так не получится.

## Что уже работает

- **Вход без номера телефона.** Аккаунт — это ник. Телефон и почта не спрашиваются.
- **Два готовых аккаунта при первом запуске:** `админ` и `админ2`, оба без пароля.
- **Создание ника** с паролем по желанию (пароль хранится не в открытом виде, а хешем).
- **Список чатов** — аккаунты этого устройства и те, с кем уже переписывался по сети;
  у непрочитанных чатов видно значок.
- **Новый чат с любым человеком** — кнопка «Новый чат» в списке: впиши ник, и переписка откроется,
  даже если человека нет среди аккаунтов устройства. Облако подскажет, если такого ника нет.
- **Один ник — один человек.** Ники бронируются в облаке: занять уже занятый ник не получится,
  а если твой ник всё-таки оказался занят кем-то другим, приложение предупредит об этом в списке чатов.
  «Админ» и «админ» считаются одним и тем же ником.
- **Переписка:** пузыри сообщений (свои — сине-зелёные справа, собеседника — слева), время, удаление переписки.
- **Связь:** два способа в одном поле адреса — свой сервер (`127.0.0.1:7777`) или облако
  (`https://проект.supabase.co` + ключ). Кнопка «Подключиться», состояние связи видно на экране чатов
  и под полем ввода; есть «подключаться при входе».
- **Облако:** связь из любой точки интернета без своего сервера; сообщение ждёт получателя в облаке,
  пока он офлайн, и удаляется, как только он его забрал.
- **Доставка с удалением:** сервер держит сообщение до подтверждения и удаляет его;
  неотданное ждёт получателя, повторная доставка не создаёт дублей.
- **Темы:** тёмная, зелёная, синяя — перекрашивают приложение целиком.
- **Язык:** русский и английский, переключатель на экране входа и в настройках.
- **Сглаживание** — настройка «Сглаживание»: четыре уровня от «Выключено» до «Максимум».
  Управляет мягкостью текста и разрешением фонового свечения; на видеокартах с Vulkan или
  DirectX 12 (запуск через `build\TNGram-качество.bat`) добавляется сглаживание краёв фигур.
  Если видеокарта старая, приложение честно пишет об этом в настройках.
- **Звук:** короткий сигнал на новое сообщение (свой — тише, чужое — заметнее). Есть включатель
  и ползунок громкости. Звуки считаются прямо в коде — в проекте нет звуковых файлов.
- **Уведомления в приложении:** карточка в углу с ником и текстом нового сообщения; сама исчезает
  через несколько секунд, щелчок открывает чат. Есть включатель.
- **Экран «Что нового»:** что изменилось в каждой версии (`Протокол.CHANGELOG`).
- **Проверка обновлений:** приложение читает `version.json` со своего сайта и, если там версия
  новее установленной, показывает предложение обновиться со ссылкой на сайт.
- **Сохранение:** вся переписка и аккаунты лежат в файле на устройстве и переживают перезапуск.

## Чего ещё нет (честно)

- **Серверной аутентификации нет.** В облаке сейчас пускают по публичному ключу: кто угодно с этим
  ключом может войти под любым ником и прочитать таблицу сообщений. Для проверки с друзьями годится,
  для 50 человек — нет: нужен вход по логину и паролю на сервере.
- **Свой сервер ничего не запоминает после перезапуска.** Недоставленные сообщения лежат в памяти:
  если закрыть `relay.bat`, они пропадут. В облаке такого нет — там сообщение ждёт в таблице.
- **Пароль аккаунта не защищает сообщения.** Сервер (и тот, кто им владеет) видит текст сообщения
  и то, кому оно отправлено. Полное шифрование — отдельная и большая задача.
- **Регистрации с проверкой личности нет:** ника достаточно. Ник бронируется в облаке по ключу
  без учёта регистра (см. шаг с SQL ниже), но пароль по-прежнему слабая защита: облако сейчас
  пускает по публичному ключу, и злоумышленник с ключом может создать ник первым.
- **Восстановления нет.** Переписка живёт только на устройстве: если файл данных удалится, вернуть её нельзя.
- Групп, голосовых сообщений, отправки файлов, звонков и сквозного шифрования — пока нет.
  Это следующие шаги.

## Где что менять

- **Тексты** — `scripts/Loc.gd`, словарь `STRINGS` (разделы `ru` и `en`).
- **Цвета и темы** — `scripts/Style.gd`, словарь `PALETTES` (`dark`, `green`, `blue`).
- **Готовые аккаунты** — `scripts/Store.gd`, строка `DEFAULT_ACCOUNTS`.
- **Пороги связи** — `scripts/net/TnNet.gd` (`CONNECT_TIMEOUT`, `CLOUD_TIMEOUT`, `CLOUD_HEARTBEAT`) и `relay/RelayServer.gd` (`RESEND_EVERY`).
- **Адрес и ключ облака** — вписываются в приложении (`Настройки → Связь`), а значения по умолчанию и
  адреса путей облака лежат в `scripts/net/Protocol.gd` (`CLOUD_SUFFIX`, `CLOUD_TABLE`, `CLOUD_REALTIME_PATH`,
  `PROFILES_TABLE`, `CLOUD_DEFAULT_URL`, `CLOUD_DEFAULT_KEY`).
- **Версия, сайт и «Что нового»** — `scripts/net/Protocol.gd` (`APP_VERSION`, `SITE_URL`, `UPDATE_FILE`,
  `CHANGELOG`) и файл `сайт/version.json` (держи номер таким же, как `APP_VERSION`).
- **Звуки** — `scripts/Sfx.gd`, словарь `SOUNDS` (частота, длина, громкость нот — считаются кодом).
- **Уровни сглаживания** — `scripts/Style.gd` (`glow_size`, `aa_font`) и `scripts/Main.gd` (`apply_aa`).
- **Название и размер окна** — `project.godot`, разделы `[application]` и `[display]`.
- **Новый экран** — добавь файл в `scripts/ui/`, затем впиши его в словарь `SCREENS` в `scripts/Main.gd`.

## Где лежат данные и как всё сбросить

```
%APPDATA%\Godot\app_userdata\TNGram\tngram_data.json
```

Удали этот файл — приложение начнётся с чистого листа (снова появятся `админ` и `админ2` без паролей).

## Как получить .exe

**Уже готов:** `build\TNGram.exe` (≈104 МБ, один файл — внутрь вшито всё, включая движок).
Рядом лежат `build\ПРОЧТИ-МЕНЯ.txt` — короткая инструкция для друга, и необязательный
`build\TNGram-качество.bat` — запуск с повышенным качеством картинки (сглаживание краёв фигур;
нужна видеокарта с Vulkan или DirectX 12). Если положить `.bat` рядом с `.exe`, его можно запускать
вместо обычного клика — если не заработает, запускай `TNGram.exe` как обычно.

Пересобрать заново (после правок в коде):

```
"C:\Program Files (x86)\Steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe" ^
  --headless --path "%~dp0." --export-release "Windows Desktop" "build/TNGram.exe"
```

Шаблоны экспорта Godot 4.7.2 уже установлены в `%APPDATA%\Godot\export_templates\4.7.2.stable\`.
Настройки экспорта — в `export_presets.cfg` (пресет «Windows Desktop», pck вшит в `.exe`, поэтому
файл ровно один — его удобно переслать).

Что сказать другу: положить `TNGram.exe` куда угодно, запустить двойным кликом, при синем окне
Windows нажать «Подробнее» → «Выполнить в любом случае» (обычное предупреждение для новых программ
без платной подписи), придумать ник и войти. Настраивать ничего не нужно — облако уже встроено.

Данные на компьютере друга лежат отдельно от твоих: `%APPDATA%\Godot\app_userdata\TNGram\tngram_data.json`.
