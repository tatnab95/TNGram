# Тнграм — приложение

Приложение мессенджера «Тнграм» на движке **Godot 4.7** (GDScript, без сторонних библиотек).
Есть интерфейс, хранение переписки **на устройстве** и связь двумя способами: через **свой
сервер-передаточник** (внутри одной сети) и через **облако Supabase** (из любой точки интернета).
В обоих случаях сервер держит сообщение ровно до момента, пока его не заберёт получатель.

## Как запустить

Двойной клик по **`start.bat`** — поднимет и сервер-передаточник (в отдельном окне), и приложение,
а ещё напечатает адрес для друзей. Адрес достаточно вписать один раз в `Настройки → Связь` — он
запоминается и переживает перезапуск. Посмотреть адрес, ничего не запуская: **`start.bat info`**.
Если Godot установлен в другом месте, открой файл `.bat` и поправь путь `GODOT_EXE` в первой строке.

Другие способы:

- двойной клик по **`run.bat`** — только приложение, без сервера;
- из редактора Godot: `Project → Open` → выбрать папку `tn-gram_godot` → `F5`;
- **`test.bat`** — автопроверки без окна: сначала интерфейс и данные, потом своя сеть;
- **`cloud_test.bat`** — проверка облачной связи по-настоящему, через интернет;
- **`relay.bat`** — только сервер-передаточник (держи открытым, пока общаешься);
- **`run_second.bat`** — второе окно приложения со своим профилем (для проверки связи на одном ПК);
- **`firewall.bat`** — открыть входящий порт `7777` в файрволе Windows (спросит права администратора).

## Облако: связь из любой точки (уже работает)

Свой сервер виден только внутри одной сети. Чтобы писать человеку из другого города, есть облако —
бесплатный проект **Supabase**. Платить не надо, свой сервер держать не надо, твой компьютер может быть
выключен (сообщение подождёт в облаке).

Адрес и ключ проекта уже готовы — впиши их один раз:

1. Открой приложение → **Настройки → Связь**.
2. В поле адреса: `https://hqmgjnloilemdwejzoyy.supabase.co`
3. В поле ключа: `sb_publishable_eyJSH1Zs1IDEeE61009XDw_cQt5ujXj`
4. Оставь галочку «Подключаться при входе» и нажми **Подключиться**. Появится «На связи как …».

Тот же ключ нужен другу — он не секретный, его можно передавать. А вот **секретный** ключ
(`service_role`) никому не показывай.

Как это работает: сообщение ложится строкой в таблицу облака. Если получатель на связи, он узнаёт о нём
мгновенно и **сразу удаляет** у себя; если офлайн — сообщение ждёт в облаке и придёт, как только он
подключится. Обещание то же, что и у своего сервера.

Проверить, что облако живо: **`cloud_test.bat`** — 26 проверок по-настоящему через интернет.
Чтобы бесплатный проект не «засыпал» после 7 дней простоя, в репозитории лежит
`.github/workflows/keepalive.yml` — он раз в сутки делает один безобидный запрос.

> **Важно про безопасность.** Сейчас облако пускает любого, у кого есть публичный ключ: серверной
> аутентификации ещё нет. Для проверки с друзьями это нормально, но **перед реальными 50 пользователями
> нужно добавить вход** (логин и пароль на сервере). Пока ключ есть у постороннего — он может прочитать
> таблицу сообщений.

## Связь: как проверить прямо сегодня

Ни аккаунтов, ни интернета, ни чужих сервисов не нужно — всё работает на твоём компьютере.

1. Запусти **`relay.bat`** — консоль напишет, что сервер слушает порт `7777`. Оставь её открытой.
2. Запусти **`run.bat`**, войди как `админ`.
3. Запусти **`run_second.bat`** — откроется второе окно со своим профилем, войди как `админ2`.
4. В каждом окне: `Настройки → Связь → адрес 127.0.0.1:7777 → Подключиться`.
   Если включишь галочку «Подключаться при входе», вставать на связь будет само.
5. Напиши что-нибудь из одного окна — сообщение появится в другом.

Что происходит в это время: сообщение сохраняется у тебя, уходит на сервер, сервер держит его и
отдаёт получателю, получатель подтверждает — и сервер **сразу удаляет** у себя. Если получатель
оффлайн, сообщение подождёт на сервере и пришлётся, как только он выйдет на связь.

Для людей в той же домашней сети подключайся не к `127.0.0.1`, а к адресу этого компьютера —
`start.bat` печатает его готовым. Windows при первом запуске может спросить «разрешить доступ» —
согласись, иначе порт будет закрыт (то же самое делает `firewall.bat`).

## Как проверить с другом из другого города

**Самый простой путь — облако.** Смотри раздел «Облако» выше: впиши адрес и ключ на обоих
компьютерах, и всё. Ни твой компьютер, ни роутер больше не нужны.

Если хочется обойтись без облака, есть ещё два пути:

1. **Tailscale** — поставь Tailscale себе и другу, войдите под одним аккаунтом. `start.bat` сам
   напечатает адрес вида `ws://100.x.y.z:7777`; продиктуй его другу, он впишет его в
   `Настройки → Связь`. Канал Tailscale сам прокладывается через интернет, роутер настраивать не надо.
   Оговорка: на бесплатном тарифе только **3 пользователя**, для большой компании не подойдёт.
2. **Проброс порта** — если провайдер даёт «белый» IP: в роутере пробрось TCP `7777` на этот
   компьютер, открой порт в файрволе (`firewall.bat`) и продиктуй другу внешний адрес. При «сером»
   IP (за NAT провайдера) так не получится.

## Что уже работает

- **Вход без номера телефона.** Аккаунт — это ник. Телефон и почта не спрашиваются.
- **Два готовых аккаунта при первом запуске:** `админ` и `админ2`, оба без пароля.
- **Создание ника** с паролем по желанию (пароль хранится не в открытом виде, а хешем).
- **Список чатов** — аккаунты этого устройства и те, с кем уже переписывался по сети.
- **Переписка:** пузыри сообщений (свои — сине-зелёные справа, собеседника — слева), время, удаление переписки.
- **Связь:** два способа в одном поле адреса — свой сервер (`127.0.0.1:7777`) или облако
  (`https://проект.supabase.co` + ключ). Кнопка «Подключиться», состояние связи видно на экране чатов
  и под полем ввода; есть «подключаться при входе».
- **Облако:** связь из любой точки интернета без своего сервера; сообщение ждёт получателя в облаке,
  пока он офлайн, и удаляется, как только он его забрал.
- **Доставка с удалением:** сервер держит сообщение до подтверждения и удаляет его;
  неотданное ждёт получателя, повторная доставка не создаёт дублей.
- **Темы:** тёмная, зелёная, синяя — перекрашивают приложение целиком.
- **Язык:** русский и английский, переключатель на экране входа и в настройках.
- **Сохранение:** вся переписка и аккаунты лежат в файле на устройстве и переживают перезапуск.

## Чего ещё нет (честно)

- **Серверной аутентификации нет.** В облаке сейчас пускают по публичному ключу: кто угодно с этим
  ключом может войти под любым ником и прочитать таблицу сообщений. Для проверки с друзьями годится,
  для 50 человек — нет: нужен вход по логину и паролю на сервере.
- **Свой сервер ничего не запоминает после перезапуска.** Недоставленные сообщения лежат в памяти:
  если закрыть `relay.bat`, они пропадут. В облаке такого нет — там сообщение ждёт в таблице.
- **Пароль аккаунта не защищает сообщения.** Сервер (и тот, кто им владеет) видит текст сообщения
  и то, кому оно отправлено. Полное шифрование — отдельная и большая задача.
- **Регистрации нет:** ника достаточно, и два человека могут назвать себя одинаково.
  Свой сервер отдаёт ник последнему подключившемуся.
- **Восстановления нет.** Переписка живёт только на устройстве: если файл данных удалится, вернуть её нельзя.
- **Начать переписку с новым человеком неудобно:** в списке чатов видны свои аккаунты и те, кто уже
  написал. Отдельной кнопки «новый чат по нику» пока нет.
- Уведомлений, отправки файлов, звонков — нет.

## Автопроверки

- **`test.bat`** — проверки своей сети, окно не нужно.
  Интерфейс и данные: **114 проверок** (аккаунты, вход, пароли, приём сообщения из сети, настройки связи —
  и своего сервера, и облачные адрес с ключом, — язык, темы, раскладка, окна подтверждения, нажатия кнопок
  как у человека, а в конце — сквозная проверка: настоящее приложение разговаривает с настоящим сервером и
  сообщение ходит в обе стороны). Связь: **21 проверка** (доставка, оффлайн-очередь, удаление после
  подтверждения, отказ без сервера, вытеснение повторного входа под тем же ником).
  Проверки идут в отдельном профиле, поэтому твои аккаунты и переписка не трогаются.
  Отчёты: `%APPDATA%\Godot\app_userdata\TNGram\smoke_report.txt` и `…\net_report.txt`.
- **`cloud_test.bat`** — проверки облака по-настоящему через интернет. Нужен интернет; проверка трогает
  только свои тестовые строки и убирает их за собой.
  - `CloudTest` — **16 проверок**: вход двух клиентов, доставка, удаление после подтверждения, ожидание
    офлайн-получателя, статистика и честный отказ при неверном ключе.
  - `CloudAppTest` — **10 проверок** «как в жизни»: настоящее приложение (экраны + данные) само выходит
    в облако под своим ником, отправляет и получает сообщение, и облако после доставки очищается.
  Отчёты: `%APPDATA%\Godot\app_userdata\TNGram\cloud_report.txt` и `…\cloud_app_report.txt`.

## Где что менять

- **Тексты** — `scripts/Loc.gd`, словарь `STRINGS` (разделы `ru` и `en`).
- **Цвета и темы** — `scripts/Style.gd`, словарь `PALETTES` (`dark`, `green`, `blue`).
- **Готовые аккаунты** — `scripts/Store.gd`, строка `DEFAULT_ACCOUNTS`.
- **Пороги связи** — `scripts/net/TnNet.gd` (`CONNECT_TIMEOUT`, `CLOUD_TIMEOUT`, `CLOUD_HEARTBEAT`) и `relay/RelayServer.gd` (`RESEND_EVERY`).
- **Адрес и ключ облака** — вписываются в приложении (`Настройки → Связь`), а значения по умолчанию и
  адреса путей облака лежат в `scripts/net/Protocol.gd` (`CLOUD_SUFFIX`, `CLOUD_TABLE`, `CLOUD_REALTIME_PATH`).
- **Название и размер окна** — `project.godot`, разделы `[application]` и `[display]`.
- **Новый экран** — добавь файл в `scripts/ui/`, затем впиши его в словарь `SCREENS` в `scripts/Main.gd`.

## Где лежат данные и как всё сбросить

```
%APPDATA%\Godot\app_userdata\TNGram\tngram_data.json
```

Удали этот файл — приложение начнётся с чистого листа (снова появятся `админ` и `админ2` без паролей).

У второго окна, запущенного через `run_second.bat`, свой файл: `tngram_data_second.json`.

## Как получить .exe

Нужны шаблоны экспорта Godot: в редакторе `Editor → Manage Export Templates → Download and Install`
(около 800 МБ). После этого `Project → Export → Windows Desktop`.

Шаблоны пока не установлены, поэтому файла `.exe` ещё нет. Настройки экспорта (`export_presets.cfg`)
тоже пока не создавались — сделаем, когда понадобится.
